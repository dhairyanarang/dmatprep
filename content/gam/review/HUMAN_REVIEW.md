<a id="gam-business-administration-fixed-price-rights-001-h1"></a>**[h1]** **Fixed-price rights at the Meridian Exchange**

<a id="gam-business-administration-fixed-price-rights-001-p1"></a>**[p1]** The Meridian Exchange sells two kinds of fixed-price right over one tonne of refined zinc. A buy-right lets whoever holds it purchase a tonne at a stated strike price on the settlement date, whatever the market is doing that day. A sell-right lets its holder sell a tonne at the strike price on the same terms. A holder is never obliged to use a right, and an unused right simply lapses. The sum paid for a right when it is bought is called the premium, and the premium is paid whether or not the right is later used.

<a id="gam-business-administration-fixed-price-rights-001-p2"></a>**[p2]** On the settlement date the exchange values every right by one rule. A buy-right is worth the settlement price minus its strike price when that difference is positive, and nothing otherwise. A sell-right is worth its strike price minus the settlement price when that difference is positive, and nothing otherwise. The net result for the holder is that value less the premium already paid, so a right that lapses leaves its holder down by exactly the premium.

| R2 | buy-right | 2550 | 35 |
| R3 | sell-right | 2400 | 80 |

<a id="gam-computational-sciences-cache-policy-001-h1"></a>**[h1]** **A cache and its replacement policy**

<a id="gam-computational-sciences-cache-policy-001-p1"></a>**[p1]** A cache keeps a small number of records close at hand so that they need not be fetched from the slow store each time. When a record is asked for and is already in the cache the request is a hit; otherwise it is a miss, the record is fetched and placed in the cache, and if the cache is full one record must be dropped to make room. The share of requests that are hits is the cache’s hit rate.

<a id="gam-computational-sciences-cache-policy-001-p2"></a>**[p2]** This system drops whichever record has gone longest without being asked for. A hit counts as an asking, so a record that is found in the cache is thereby moved to the back of the queue for eviction; a record that is merely written back to the slow store is not, because writing is not a request for the record.

<a id="gam-computational-sciences-cache-policy-001-t1"></a>**[t1]** *Four caches on one machine, as measured over a working day.*

| Cache | Records held | Hit rate |
|---|---|---|
| Index cache | 64 | 97 per cent |
| Document cache | 512 | 61 per cent |
| Thumbnail cache | 2048 | 88 per cent |
| Session cache | 128 | 79 per cent |

<a id="gam-computational-sciences-cache-policy-001-p3"></a>**[p3]** A hit rate is a property of the pairing of a cache with the pattern of requests it happens to meet. The figures above were measured on one working day’s traffic; a different pattern of requests would give different figures on the same caches, and they are not a ranking of the caches in themselves.

<a id="gam-computational-sciences-finite-automata-001-h1"></a>**[h1]** **Two machines that read strings of symbols**

<a id="gam-computational-sciences-finite-automata-001-p1"></a>**[p1]** A finite automaton reads a string of symbols one at a time from left to right, and remembers exactly one thing: which state it is currently in. It begins in a designated start state. Each symbol it reads moves it from its current state to another state, according to a fixed transition rule. When the string runs out the automaton accepts it if the machine has finished in an accepting state, and rejects it otherwise. An automaton is called deterministic, written DFA, when its transition rule gives exactly one next state for every pairing of a current state with a symbol: no pairing may be left out, and none may offer a choice.

<a id="gam-computational-sciences-finite-automata-001-p2"></a>**[p2]** A nondeterministic automaton, written NFA, relaxes that requirement. For a given state and symbol it may list no next state at all, or it may list several. Reading a string then traces not a single path but a set of them at once. Such a machine accepts a string when at least one of those paths ends in an accepting state, and rejects it only when every path fails to do so. The machine is never described as choosing between paths, and nothing in the rule tells it which to prefer.

<a id="gam-computational-sciences-finite-automata-001-t1"></a>**[t1]** *Table 1 — transition rule for machine M, which is deterministic*

| State | On symbol a | On symbol b |
|---|---|---|
| Q0, the start state | Q1 | Q0 |
| Q1 | Q1 | Q2 |
| Q2, an accepting state | Q1 | Q0 |

<a id="gam-computational-sciences-finite-automata-001-t2"></a>**[t2]** *Table 2 — transition rule for machine N, over the same two symbols*

| State | On symbol a | On symbol b |

| P0, the start state | P0 and P1 | P0 |

<a id="gam-mathematics-two-stage-inspection-001-h1"></a>**[h1]** **A two-stage inspection**

<a id="gam-mathematics-two-stage-inspection-001-p1"></a>**[p1]** Every item made on a line goes through a first inspection, and a proportion of items is flagged there for a closer look. <a id="gam-mathematics-two-stage-inspection-001-p2"></a>**[p2]** The rejection rate is quoted as a proportion of the items that reach the second inspection, and not as a proportion of everything the line makes. <a id="gam-mathematics-two-stage-inspection-001-t1"></a>**[t1]** *Flag and rejection rates for four production lines.*

| Line | Flag rate | Rejection rate |
|---|---|---|
| Line A | 12 per cent | 25 per cent |
| Line B | 8 per cent | 15 per cent |
| Line C | 20 per cent | 5 per cent |
| Line D | 5 per cent | 40 per cent |

<a id="gam-mathematics-two-stage-inspection-001-p3"></a>**[p3]** Both rates are properties of the line as it is currently set up. Neither moves with the number of items put through it, so a line that runs for longer rejects more items but does not reject a larger share of them.

<a id="gam-social-sciences-coding-agreement-001-h1"></a>**[h1]** **Coding open answers, and checking the coders**

<a id="gam-social-sciences-coding-agreement-001-p1"></a>**[p1]** Answers written in a respondent’s own words are turned into categories before they can be counted. The list of categories, with a written rule for what belongs in each, is the coding frame. A share of the answers is double-coded, meaning that two coders work on the same answers without seeing each other’s decisions, and the proportion of those answers they place in the same category is the pair’s agreement rate.

<a id="gam-social-sciences-coding-agreement-001-t1"></a>**[t1]** *Agreement rates for four pairs of coders, on the same set of double-coded answers.*

| Pair | Answers double-coded | Agreement rate |
|---|---|---|
| Pair 1 | 300 | 91 per cent |
| Pair 2 | 300 | 74 per cent |
| Pair 3 | 300 | 88 per cent |
| Pair 4 | 300 | 83 per cent |

<a id="gam-social-sciences-coding-agreement-001-p2"></a>**[p2]** Where an answer could be placed in more than one category, the frame directs the coder to the category named earliest in the list, and to record the answer as contested. Contested answers are counted in the category they were given and are also set aside for the frame to be revised at the end of the round.

<a id="gam-social-sciences-coding-agreement-001-p3"></a>**[p3]** An agreement rate measures whether two coders read the frame the same way. It says nothing about whether the frame captures what the respondents meant: two coders can apply a poorly drawn category with perfect consistency, and their agreement will be as high as if the category were a good one.

<a id="gam-social-sciences-coding-agreement-001-p4"></a>**[p4]** A coder who has seen the other coder’s decisions is no longer coding independently, and the pair’s figure is not an agreement rate at all. The one condition the procedure rests on is that the two work unaware of each other.

<a id="gam-social-sciences-two-stage-sampling-001-h1"></a>**[h1]** **Designing the Rothcarn household survey**

<a id="gam-social-sciences-two-stage-sampling-001-p1"></a>**[p1]** The survey team must reach households in a district of 4000 households, arranged in 50 blocks of 80 households each. Rather than list every household in the district, the team draws its sample in two stages. In the first stage it selects 10 of the 50 blocks, every block having the same chance of being chosen. In the second stage it selects 8 households from inside each chosen block, every household in that block again being equally likely. A household can enter the sample only if its own block was selected at the first stage.

<a id="gam-social-sciences-two-stage-sampling-001-p2"></a>**[p2]** The chance that any particular household joins the sample is the chance that its block is selected multiplied by the chance that the household is then drawn from within that block. The team calls a plan self-weighting when that product works out the same for every household in the district, and it treats the property as worth protecting, because a plan that loses it needs every answer reweighted before any total can be reported.
